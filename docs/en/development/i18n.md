# Management console internationalization

[简体中文](../../development/i18n.md) · [Development guide](README.md)

The console supports `zh-CN` and `en`. See the [console guide](../user/console.md#choose-a-language) for language selection and preferences. Display language does not change MCP tool schemas, database entities, or audit records.

## Frontend

`web/assets/i18n.js` selects the language and substitutes parameters; `en.js` holds English translations keyed by Chinese source messages. Priority is a valid URL `lang` parameter, the browser preference scoped to this console address, the first supported browser language, then English. Chinese and English regional variants are supported. If storage is blocked, the URL retains the selection for the tab; form contents and credentials are never persisted for switching.

The application imports the translation function as `tr`. Do not replace all DOM text or pass entity names, aliases, secrets, file contents, or other user data through translation. Use parameters such as `{0}` for dynamic messages. Substitution is a single literal replacement pass; retain `esc` at existing HTML output boundaries. Switching reloads the current page and keeps the administrator JWT for the same API root. Unsaved login, password, or policy inputs, and submissions in progress, prevent switching to avoid lost input or replayed writes.

Add an English entry for each new message with the same parameters. `npm run check` verifies static message coverage, catalog parameters, and language selection rules. Modules must be served through the `web/embed.go` asset allowlist and work under a fixed base path.

## Management API

`internal/api/i18n.go` selects a language from `Accept-Language` regional variants and quality weights. Missing or unsupported preferences default to Chinese for existing clients. Selection is recorded in the current response's `Content-Language`; there is no mutable global locale. Responses add `Vary: Accept-Language`.

Only server-owned text is translated: problem `message`, post-execution audit `warning`, and privilege-check `detail`. HTTP status, machine-readable codes, entity contents, audit fields, JWT/JWE, and MCP protocols remain unchanged. Underlying English diagnostics and user data inside them are not replaced. Both normal API requests and JWE challenge requests explicitly send the frontend language.

## Validation

Alongside the dual-backend suite, browser regressions cover English pages and mobile layout, English login and errors, preserved Chinese user data, switching and persistence, storage-restricted fallback, and protection of unsaved inputs. Real HTTP/HTTPS acceptance also checks that switching preserves the JWT and current page. Language/API integration tests run against SQLite and PostgreSQL.
