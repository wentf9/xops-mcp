# 管理控制台国际化

[English](../en/development/i18n.md) · [开发指南](README.md)

控制台支持 `zh-CN` 和 `en`。语言切换和偏好说明见[控制台指南](../user/console.md#选择语言)。MCP 工具 schema、数据库实体和审计记录不因显示语言改变。

## 前端

`web/assets/i18n.js` 负责语言选择与参数替换，`en.js` 保存以中文原文为键的英文词典。选择顺序是有效的 URL `lang` 参数、当前控制台地址下保存的浏览器偏好、浏览器首个支持的语言、英文回退。支持中文和英文区域变体。存储不可用时用 URL 保留本标签页选择，不持久化表单或凭据。

应用通过 `tr` 别名调用翻译函数；不要用 DOM 全文替换或把实体名称、别名、秘密、文件内容等用户数据送入翻译函数。动态文案使用 `{0}` 等参数，替换为单次字面值替换；继续在原 HTML 输出边界使用 `esc`。语言选择重新载入当前页面，保留同一 API 根下的管理员 JWT。未保存的登录、改密、策略输入或正在提交的表单会阻止切换，避免丢失输入或重放写请求。

新文案必须同时添加英文词条，参数集合必须一致。`npm run check` 检查静态文案覆盖、词典参数和语言选择规则。模块须通过 `web/embed.go` 的资源白名单提供，并保持固定前缀可用。

## 管理 API

`internal/api/i18n.go` 从 `Accept-Language` 的区域变体与质量权重选择语言。未指定或不支持时默认中文，以兼容已有客户端。选择记录在当前响应的 `Content-Language` 中，无全局可变语言状态。响应添加 `Vary: Accept-Language`。

只翻译服务拥有的消息文本：错误 `message`、执行后审计警告 `warning` 和提权检查 `detail`。HTTP 状态、机器可读错误码、实体内容、审计字段、JWT/JWE 和 MCP 协议保持不变；底层英文诊断及其中的用户数据不做字符串替换。前端普通 API 和 JWE 挑战请求都显式传递当前语言。

## 验证

除常规双后端测试外，浏览器回归覆盖英文页面及移动布局、英文登录和错误提示、中文用户数据保留、语言切换与持久化、存储受限回退、未保存输入保护。真实 HTTP/HTTPS 浏览器验收还验证切换语言后 JWT 和当前页面保持有效。语言/API 集成测试同时使用 SQLite 和 PostgreSQL。
