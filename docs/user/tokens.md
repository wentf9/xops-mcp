# MCP Token 管理

[English](../en/user/tokens.md) · [使用指南](README.md)

登录控制台后打开“MCP Token”。多个 Token 可以同时使用，建议为每个客户端分别创建一个，名称可填写设备或用途。

## 创建与连接

1. 点击“新建 Token”，填写名称、允许访问的节点范围，选择是否启用和到期时间。到期时间留空表示永不过期。
2. 创建后复制完整 Token，保存到对应 MCP 客户端的访问凭据配置中。
3. 按[客户端连接说明](console.md#连接-mcp-客户端)填写服务地址。

完整 Token 只在创建完成时显示一次。列表只显示名称、凭据前缀、节点范围、状态及时间，之后无法查看原文。丢失时创建新 Token，并吊销不再使用的 Token。普通 HTTP 页面无法自动复制时，可在文本框中选中后使用复制快捷键。

## 绑定允许访问的节点

“允许访问的节点”提供两种范围：

- **全部节点**：允许访问当前所有节点，也包含以后新增的节点。升级前已有的 Token 保持此范围。
- **指定节点**：只允许访问勾选的节点，可按名称、别名或节点 ID 搜索后多选。未勾选任何节点表示无节点访问权限。

点击 Token 的“编辑”可以随时调整范围。节点改名或更换别名不会改变绑定；删除后重建同名节点需要重新勾选。编辑窗口会保留并标记已删除的绑定，可取消勾选移除。停用节点仍受节点本身的禁用限制。

客户端的节点列表仅显示其允许访问的节点。通过名称、别名或 ID 指定目标，也必须在该 Token 的范围内；批量操作中的每个目标都要获得授权。允许访问某个节点时，可经其已配置的跳板连接，不会因此获得直接操作跳板节点的权限。所有 Token 仍受统一操作策略约束。

## 停用、恢复和吊销

“编辑”可以重命名、调整节点范围和到期时间，以及勾选或取消“启用 Token”。临时停用可以恢复；“吊销”永久停止使用该凭据，不能重新启用。到期的 Token 无法认证，需调整到期时间或创建新的 Token。

变更立即用于后续 MCP 请求，无需重启。文件传输即使已经取得短期传输凭据，也会在开始传输和提交上传时重新检查 Token 状态及节点范围。已经获准开始的操作不保证中止。仍有效的 Token 可以查询或取消自己先前的文件任务，即使目标已从允许范围移除；查询已有结果不会重新执行远端操作。不同客户端不能混用 MCP 会话或查询、取消彼此的文件任务。

Token 不授予控制台管理权限。创建、编辑和吊销操作会记入审计。

## 预置初始 Token

需要在打开控制台之前连接 MCP 时，可以使用 `keygen --out mcp.token` 生成文件，并在配置中设置 `mcp_token_file: mcp.token`。文件权限为 `0600`，相对路径以配置文件所在目录为准。

服务首次读取该凭据时，将其登记为 `initial-token`，之后与其他 Token 一样在控制台管理。重启不会恢复已停用或吊销的凭据。登记完成后可以同时移除配置项和文件；客户端继续使用原 Token。无需预置时，省略此配置项。

备份数据库会保留 Token 的节点范围、有效期、状态和验证记录。完整 Token 应由使用它的客户端妥善保存。
