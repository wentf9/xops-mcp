# MCP Token 管理

[English](../en/user/tokens.md) · [使用指南](README.md)

登录控制台后打开“MCP Token”。多个 Token 可以同时使用，建议为每个客户端分别创建一个，名称可填写设备或用途。

## 创建与连接

1. 点击“新建 Token”，填写名称，选择是否启用和到期时间。留空表示永不过期。
2. 创建后复制完整 Token，保存到对应 MCP 客户端的访问凭据配置中。
3. 按[客户端连接说明](console.md#连接-mcp-客户端)填写服务地址。

完整 Token 只在创建完成时显示一次。列表只显示名称、凭据前缀、状态及时间，之后无法查看原文。丢失时创建新 Token，并吊销不再使用的 Token。普通 HTTP 页面无法自动复制时，可在文本框中选中后使用复制快捷键。

## 停用、恢复和吊销

“编辑”可以重命名、调整到期时间，以及勾选或取消“启用 Token”。临时停用可以恢复；“吊销”永久停止使用该凭据，不能重新启用。到期的 Token 无法认证，需调整到期时间或创建新的 Token。

变更立即用于后续 MCP 请求，无需重启。已经开始的操作不保证中止；已签发的短期文件传输凭据仍按原有效期和授权范围处理。不同客户端不能混用 MCP 会话或查询、取消彼此的文件任务。

所有 Token 当前使用同一套节点和操作策略，不能为单个客户端单独分配节点权限。Token 不授予控制台管理权限。创建、编辑和吊销操作会记入审计。

## 预置初始 Token

需要在打开控制台之前连接 MCP 时，可以使用 `keygen --out mcp.token` 生成文件，并在配置中设置 `mcp_token_file: mcp.token`。文件权限为 `0600`，相对路径以配置文件所在目录为准。

服务首次读取该凭据时，将其登记为 `initial-token`，之后与其他 Token 一样在控制台管理。重启不会恢复已停用或吊销的凭据。登记完成后可以同时移除配置项和文件；客户端继续使用原 Token。无需预置时，省略此配置项。

备份数据库会保留 Token 的有效期、状态和验证记录。完整 Token 应由使用它的客户端妥善保存。
